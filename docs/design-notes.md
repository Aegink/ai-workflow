# 设计说明：为什么是这样

> **来源**：本文档描述的六阶段框架与「Skill / Artifact / Gate」组织方式，出自 **czm**（[@czm15053](https://github.com/czm15053)）的长文
> 《[从 AI 写代码到 AI 工作流 · 一次需求的两条命，和救回它的六个阶段](https://czm15053.github.io/ai-workflow-six-stages/)》。
> 下面记录的是**本仓库在实现那套方法论时的取舍**，不是方法论本身。

这份文档记录本套件的几个关键取舍。它不是教程，是"为什么这么做"的备忘——
方便你以后改规则时知道哪些是刻意的。

---

## 1. 为什么是"多份同源文件"而不是一份

不同工具认不同的文件名：

| 工具 | 认的文件 |
|---|---|
| Codex / Cursor / 多数 Agent | `AGENTS.md` |
| Claude Code | `CLAUDE.md` |
| Gemini CLI | `GEMINI.md` |
| GitHub Copilot | `.github/copilot-instructions.md` |
| Windsurf | `.windsurf/rules/*.md` |
| Cursor（常驻规则） | `.cursor/rules/*.mdc`（需 frontmatter） |

如果每个都手工维护一份，必然漂移。所以：**`AGENTS.md` 是唯一真身，其余全部软链到它**。
只有 `.cursor/rules/*.mdc` 例外——它需要 `alwaysApply: true` 的 frontmatter，软链过去会把那几行也变成契约的一部分，所以由 `install.sh` 生成（frontmatter + 全文）。

代价：改了 `AGENTS.md` 后，Cursor 那份 `.mdc` 要重跑一次 `install.sh` 才同步。README 里写明了。

---

## 2. 为什么用"任务分级"而不是"每件事都走六段"

流程本身有成本。给"改个错别字"套上 PRD + 设计文档 + 任务树 + 交接记录，流程成本会高过任务本身，
结果就是**人开始绕过流程**——一旦绕过成为习惯，真正的 L3 任务也保不住了。

所以分成 L0–L3：**小任务直接做，大任务全走**。
关键细节是**升级信号**：写清楚"什么时候该升档"，并规定"拿不准就上一级、AI 主动提议升档、不许自行降档"。
降档是最危险的——它没有任何提示，风险静默地被接受。

---

## 3. 为什么 Gate 要写成"硬门禁"而不是"建议"

"建议在实现前先确认关键取舍"这种话，模型（和人）都会点头，然后跳过。
所以每条 Gate 都写成**否定式、可判定**的：

> Spec 未成型 → **禁止**拆任务。

再配合 `实现许可` 开关 + PreToolUse 钩子，Gate 从"建议"变成"物理上过不去"。
这是本套件和普通 prompt 模板最大的区别。

---

## 4. 为什么状态要落盘，而不是靠模型记忆

长对话会**上下文腐烂**（Context Rot）：输入越长，早期确认的约束被稀释得越厉害。
换会话、换模型、换工具，记忆直接归零。

所以设计成：

- 会话**开始** → 读 `state.md`
- 会话**结束** → 写 `state.md`（+ 必要时写 `handoff.md`）
- 中间所有"我们说好了" → 写进 `.aiworkflow/`

于是交接的对象不是"记忆"，而是**文件**。
这也解释了为什么要有 `stop.sh`：不检查的话，"收尾更新状态"永远是第一个被跳过的事。

---

## 5. 为什么 `handoff` 要求"引用而非复制"

复制会产生**第二份事实源**，而第二份一定先过期。
下一位沿着引用读到的是最新版本，沿着复制读到的是快照——而他不知道那是快照。

同理，`.aiworkflow/` 里的五个文件各有明确边界，**同一事实只存一处**：
需求规则在 `spec.md`，任务在 `tasks.md`，决策理由在 `decisions.md`，其余引用它们。

---

## 6. 为什么钩子脚本要 fail-open

`pre-tool-use.sh` 用轻量正则解析 JSON。如果项目路径里出现了引号导致解析失败，
**取不到值时一律放行**。

理由：这套工具的失败模式必须是"**没拦住**"，而不是"**把人挡在门外**"。
一个偶尔拒绝合法写入的钩子，会在第一天就被卸载——然后所有强制力一起消失。

---

## 7. 为什么同时给 Cursor 规则和 Claude Code 钩子

因为强制力是有层级的（见 README 表格）。
同一份契约，在不同工具上能拿到的上限不同：

- 有钩子的工具 → 直接给它最强的那一层
- 只会自动加载的工具 → 至少保证契约被自动注入
- 纯聊天工具 → 给一份能粘进自定义指令的短版

**不假装所有工具都一样强**，而是明确标出每一档的真实力，让人自己判断够不够。

---

## 8. 已知取舍

| 取舍 | 选了什么 | 代价 |
|---|---|---|
| 单文件 vs 多份 | 单文件真身 + 软链 | 需要支持软链的文件系统；Cursor 那份要重跑安装 |
| 强制 vs 易用 | 默认 `实现许可: yes`（不拦），只有显式 `no` 才拦 | 默认不强制，需要用户/模型主动把关 |
| 严格 vs 不误伤 | 解析失败就放行 | 极端情况下会漏拦 |
| 全量 vs 精简 | 契约 10KB，一次注入 | 消耗一部分上下文 |

最后一条值得留意：**契约太长会挤占上下文**。如果你觉得 10KB 太多，
可以把 `AGENTS.md` 拆成"核心 20 行 + 详细文档按需读"，但核心那 20 行里
**启动协议、任务分级、Gate 列表**一个都不能少。
